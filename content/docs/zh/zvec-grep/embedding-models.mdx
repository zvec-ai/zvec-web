Embedding 模型会影响语言覆盖、内存、输入长度、索引速度与语义质量。

## 建议起点

直接使用内置默认模型：

```bash
zg --index
```

未配置模型时，Zvec-Grep 使用 `local/potion-code-16m-v2`。仅当工作区对语言覆盖、输入长度或检索质量有不同要求时再更换模型。

## 配置本地模型

### 默认值与覆盖

新索引依次读取 `--embedding`、`ZVEC_GREP_EMBEDDING` 和全局默认配置。以下是三种相互独立的用法：

```bash
# 选择并保存此工作区索引使用的模型
zg --index --embedding local/potion-multilingual-128m

# 设置后续新索引的全局默认模型
zg --config model set local/potion-multilingual-128m --default

# 仅覆盖当前进程的默认模型
ZVEC_GREP_EMBEDDING=local/potion-retrieval-32m zg --index
```

### 支持的本地模型

| 模型 | 适用场景 | 运行时 |
| --- | --- | --- |
| `local/potion-code-16m-v2` | 快速建立代码索引 | Model2Vec FP16 |
| `local/potion-retrieval-32m` | 英文文档 | Model2Vec FP32 |
| `local/potion-multilingual-128m` | 多语言文档 | Model2Vec FP32 |
| `local/all-minilm-l6-v2` | 较短的英文文本 | ONNX Q4 |
| `local/bge-small-en-v1.5` | 英文段落 | ONNX Q4 |
| `local/multilingual-e5-small` | 轻量多语言检索 | ONNX Q8 |
| `local/jina-embeddings-v2-base-code` | 长上下文、多语言代码 | ONNX Q8 |
| `local/gte-modernbert-base` | 较长的英文文档 | ONNX Q4 |
| `local/nomic-embed-text-v1.5` | 较长的英文文档与查询 | ONNX Q4 |
| `local/embeddinggemma-300m` | 多语言代码与文档 | GGUF Q8_0 |
| `local/qwen3-embedding-0.6b` | 更高容量的多语言检索 | GGUF Q8_0 |

### 设备与缓存

设备支持取决于模型后端、平台和已安装的运行时：

- Potion 模型使用 CPU。
- GGUF 模型支持 CPU、macOS 上的 Metal，以及受支持的 Linux/Windows x64 安装中的 CUDA。
- ONNX 模型在 macOS 上使用 CPU，包括显式指定 `metal` 的情况。Linux/Windows x64 的 CUDA 需要匹配的运行时；兼容的 Windows 运行时也可以使用 DirectML。
- Vulkan 需要自定义构建或运行时，发布的安装包不包含该支持。

```bash
zg --index --embedding local/jina-embeddings-v2-base-code --device auto
zg --config model set local/jina-embeddings-v2-base-code --device cpu
```

可通过 `ZVEC_GREP_DEVICE` 临时覆盖设备。本地模型默认缓存在 `~/.zvec-grep/models`，可通过 `--model-cache` 或 `ZVEC_GREP_MODEL_CACHE` 修改。

`zg --index` 显式传入的 `--device` 和 `--model-cache` 会保存到工作区；搜索时传入这些参数则只影响本次查询及其刷新。

### 更换本地模型

已有索引沿用建索引时保存的模型。更换模型需要重建，仅更换设备则不需要。

```bash
zg --index --rebuild --embedding local/potion-multilingual-128m
```

## 配置远程模型

远程模型无需本地推理，但会将已授权的工作区内容和查询发送给所配置的提供方。

### 支持的远程模型

| 模型 | 适用场景 |
| --- | --- |
| `qwen/text-embedding-v4` | 托管文本检索 |
| `qwen/qwen3.7-text-embedding` | 超长文本输入 |
| `qwen/qwen3-vl-embedding` | 通过多模态接口进行文本检索 |

Zvec-Grep 当前只索引文本，即使所选模型本身支持图片也是如此。

### 配置 Provider

```bash
zg --config provider set qwen --api-key "$DASHSCOPE_API_KEY"
zg --config model set qwen/text-embedding-v4 --default
```

### 授权远程访问

Provider 凭据只用于访问服务，不等于允许传输数据。可以只授权一次命令，或为当前工作区持续授权：

```bash
zg --index --embedding qwen/text-embedding-v4 --allow-remote

zg --auth grant --capability embedding --scope workspace \
  --embedding qwen/text-embedding-v4
```

使用 `zg --auth status` 查看授权，使用 `zg --auth revoke` 撤销授权。

### 更换远程配置

更换模型或 Endpoint 需要重建索引，仅更换 API Key 则不需要。

## 配置自定义 HTTP 模型

实现 [OpenAI 文本 Embedding 协议](https://developers.openai.com/api/reference/resources/embeddings/methods/create)的服务可以通过配置使用，无需添加内置模型条目。别名以 `http/` 开头，用于在 zg 中选择模型；`http.model` 则是发送给服务的实际模型 ID。

将以下条目合并到 `~/.zvec-grep/config.json`（Windows 为 `%USERPROFILE%\.zvec-grep\config.json`），并按模型的实际能力设置维度和输入上限：

```json
{
  "version": 1,
  "models": {
    "http/my-embedding": {
      "endpoint": "http://127.0.0.1:8080/v1",
      "http": {
        "model": "my-served-model",
        "dimension": 768,
        "maxInputTokens": 2048,
        "auth": "none"
      }
    }
  }
}
```

通过现有 CLI 参数选择模型：

```bash
zg --index --embedding http/my-embedding --allow-remote
zg --config model set http/my-embedding --default
```

即使服务运行在 localhost，也需要授权传输内容。可通过 `zg --auth grant --capability embedding --scope workspace --embedding http/my-embedding` 保存工作区授权。MCP 索引配置与索引操作也可以使用相同的模型引用。

### Endpoint 与认证

以 `/v1` 或 `/v1/` 结尾的地址会解析为 `/v1/embeddings`；`https://embeddings.example.com/custom/encode` 这样的完整地址则按原路径使用。只接受不含用户信息、查询参数或片段的 HTTP(S) URL。不跟随重定向，以确保请求只到达已授权的地址。

`auth` 为必填项。使用 `"auth": "none"` 时，zg 不发送 Authorization 请求头，也不会继承其他 Provider 的密钥。需要 Bearer 认证时，改用环境变量引用：

```json
"auth": "bearer",
"apiKeyEnv": "EMBEDDING_API_KEY"
```

在运行 zg 的进程环境中设置该变量；常驻 daemon 需要在自己的环境中读取它。保存的配置只包含变量名，不包含密钥。不要把密钥放入 Endpoint，也不要用 Qwen Provider 配置来认证 `http/` 模型。

### 限制与请求格式

请求包含 `model` 和 `input`。响应必须为每个输入返回一个带索引的 `data[].embedding` 数值向量。zg 会恢复输入顺序，并拒绝索引缺失、重复、维度错误或包含非有限数值的响应。

| `http` 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `model` | 必填 | 发送给服务的模型 ID。 |
| `dimension` | 必填 | 预期向量维度，必须大于零。 |
| `maxInputTokens` | 必填 | 用于分块的输入预算，应按服务的 tokenizer 设置合适的上限。 |
| `auth` | 必填 | `none` 或 `bearer`。 |
| `apiKeyEnv` | 无 | `bearer` 必填；`none` 不允许设置。 |
| `metric` | `cosine` | `cosine`、`dot_product` 或 `euclidean`。 |
| `maxBatchSize` | `1` | 单次请求的最大输入数量。 |
| `timeoutMs` | `60000` | 单次请求超时，单位为毫秒。 |
| `queryPrefix` / `documentPrefix` | 空 | 分别添加到查询和文档前的文本，适用于需要不同指令的模型。前缀占用输入预算。 |
| `singleInput` | `false` | 将 `input` 作为单个字符串发送，而非数组。要求 `maxBatchSize: 1`。 |
| `sendDimensions` | `false` | 在请求中发送 `dimensions`，仅在服务支持时开启。 |
| `sendEncodingFormat` | `false` | 发送 `encoding_format: "float"`；否则服务须默认返回数值向量。 |

所有数值限制必须为正数。索引并发使用 `--embedding-concurrency` 控制；HTTP 模型沿用现有的取消和有界重试机制，包括限流时的 `Retry-After`。默认不发送可选请求字段。

### 已有索引

模型定义和解析后的 Endpoint 会随索引保存。修改或删除全局条目不会静默改变已有索引的向量空间；搜索与刷新沿用保存的定义，daemon 重启后也是如此。Bearer 密钥仍从指定环境变量读取。

这适用于所有 `http` 字段，包括限制、超时、请求格式和认证设置。如需更改任何已保存字段或 Endpoint，请修改全局条目并显式重建。同一环境变量提供的密钥值发生变化时无需重建；更改已保存的 `apiKeyEnv` 变量名则需要重建。

```bash
zg --index --rebuild --embedding http/my-embedding --allow-remote
```

会混合不同向量空间的 Endpoint 覆盖将被拒绝。内置 `local/` 和 `qwen/` 模型的配置及默认值保持不变。
