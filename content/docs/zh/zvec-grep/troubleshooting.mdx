先运行以下四项检查，大多数问题都可以由此定位：

```bash
zg version
zg status
zg server status
zg help
```

## 1. 找不到 `zg` 命令

确认已安装 Node.js 22 或更新版本，然后重新安装全局包：

```bash
node --version
npm install -g @zvec/zvec-grep
zg version
```

如果 npm 安装成功，但 Shell 仍然找不到 `zg`，请确认 npm 全局可执行文件目录已经加入 Shell 的 `PATH`。

## 2. 索引不存在或未就绪

从目标工作区根目录运行命令，并检查索引状态：

```bash
pwd
zg status --check-ready
```

使用 `zg index` 创建索引或增量刷新。只有在更换 Embedding 模型，或确实需要替换索引配置时才重建：

```bash
zg index
zg index --rebuild --embedding local/potion-code-16m-v2
```

如果查询必须包含最新修改，可以等待刷新完成：

```bash
zg query "release checklist" --refresh wait
```

## 3. 搜索结果为空或质量较弱

增加 `--limit` 前，先检查检索路径是否正确：

1. 已知字面量、标识符、路径或正则时使用 `--rg`。
2. 已知重要术语但需要相关性排序时使用 `--fts`。
3. 不清楚措辞或位置时使用默认混合检索。
4. 工作区范围过大时使用 `-g`、`-t` 或 `-T` 缩小范围。
5. 确认文件类型已被索引，且所选模型适合当前内容。

结果仍然异常时，打开诊断信息：

```bash
zg query "authentication flow" --debug --trace
zg index --debug
```

继续阅读[选择检索模式](../search/)、[控制搜索范围与结果](../search-scope/)或[支持的内容](../supported-content/)。

## 4. AI Agent 无法使用 Zvec-Grep

先检查本地 MCP Server：

```bash
zg server status --check-ready
```

然后重新安装托管集成，并新建一个 Agent 会话：

```bash
zg install --target codex --yes
```

需要时将 `codex` 替换为 `claude`、`cursor` 或 `opencode`。使用一个措辞或位置未知的工作区概念问题进行测试。对于精确标识符或文件名，Agent 使用自身的 grep 而不是 Zvec-Grep 属于正常行为。

## 5. 远程 Embedding 被拒绝

MCP 工具批准与远程数据授权是两套独立权限。先检查当前工作区授权：

```bash
zg auth status
```

可以为工作区授予长期权限，也可以只授权单次命令：

```bash
zg auth grant --capability embedding --scope workspace --embedding qwen/text-embedding-v4
zg query "authentication flow" --allow-remote
```

如果查询或工作区内容不能离开本机，请使用本地模型。

## 6. 安全重置

重建会保留工作区，只重新创建索引；Drop 则会永久删除索引：

```bash
zg index --rebuild --embedding local/potion-code-16m-v2
zg index --drop --yes
```

<Callout type="warn" title="Drop 是破坏性操作">
  `zg index --drop --yes` 会删除工作区索引，但不会删除源文件。重新构建索引前，索引检索将不可用。
</Callout>

请附上安装版本、操作系统、失败命令、相关 `zg status` 输出，以及经过脱敏的 `--debug` 诊断信息。提交前请移除 API Key、Token、私有路径和敏感内容片段。
