Zvec-Grep 向人与 AI Agent 提供同一个本地搜索层。理解以下四个概念，就能看清各组件之间的关系。

## 1. 工作区

**工作区**是 Zvec-Grep 搜索的本地目录，可以包含源代码、文档、配置、研究资料、知识库导出或混合文本内容。

命令默认使用当前目录，也可以显式指定根目录：

```bash
zg index /absolute/path/to/workspace --embedding local/potion-code-16m-v2
```

## 2. 内容提取与索引

Zvec-Grep 扫描被选中的文件，并尽可能保留代码符号与签名、Markdown 标题与面包屑等结构；无法结构化提取时则回退为纯文本切块。

提取后的片段进入两个互补的数据层：

- 用于 BM25 / 全文排序的词法数据；
- 用于语义相似度的向量数据。

工作区索引保存在 `<workspace>/.zvec-grep/`。

## 3. 检索路径

| 路径 | 最适合 | 是否需要索引 |
| --- | --- | --- |
| 混合索引检索 | 语义加关键词证据 | 是 |
| FTS / BM25 | 已知词语的相关性排序 | 是 |
| 向量检索 | 不清楚具体措辞的概念 | 是 |
| 托管 ripgrep | 精确文本、符号、路径与正则 | 否 |

混合检索可以联合词法与向量候选并融合排序；托管 ripgrep 直接扫描工作区文件，默认穷举匹配。

## 4. 人与 Agent

人与脚本通过 `zg` CLI 使用；Agent 连接仅监听本地回环地址的 MCP Server。两条路径调用同一个搜索引擎，并返回以文件为中心的证据。

```text
工作区文件 → 提取与索引 → Zvec-Grep 搜索引擎
                            ├─ zg CLI → 人或脚本
                            └─ 本地 MCP → AI Agent
```

`server` 与 `direct` 模式只影响进程生命周期和协调方式，不改变检索行为。绝大多数终端用户保持默认的 `auto` 即可。
