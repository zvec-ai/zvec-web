Collection 加载完成后，你可以检查其结构、配置及运行时状态，以更好地了解它的组织方式和运行情况。这在开发、调试或监控系统时尤为有用。

<Accordions type="single">
  <Accordion title="代码示例">

  ```python tab="Python" title="打开 Collection" tab-group="code-demo"
  import zvec

  # [!code word:collection]
  collection = zvec.open(path="/your/specified/path/")

  print(collection.schema)  # 查看 Schema [!code highlight]
  ```

  ```ts tab="Node.js" title="打开 Collection"
  import { ZVecCollection, ZVecOpen } from "@zvec/zvec";

  // [!code word:collection]
  const collection: ZVecCollection = ZVecOpen("/your/specified/path/");

  console.log(collection.schema.toString());  // 查看 Schema [!code highlight]
  ```

  ```java tab="Java" title="打开 Collection"
  import org.zvec.binding.*;

  // [!code word:collection]
  Collection collection = Zvec.open("/your/specified/path/", null);

  // 查看 schema
  try (CollectionSchema schema = collection.getSchema()) {   // [!code highlight]
      System.out.println(schema.getName() + " " + schema.getAllFieldNames());
  }
  ```

  </Accordion>
</Accordions>

## 快速参考

| 属性 | 说明 |
| -------- | ----------- |
| `Collection.schema` | Collection 的结构和字段 (如向量维度、数据类型) |
| `Collection.stats` | 运行时指标，如 document 数量和索引构建进度 |
| `Collection.option` | 运行时配置 (如只读模式、内存映射) |
| `Collection.path` | Collection 目录的具体路径（仅 Python 和 Node.js） |

  ```bash tab="Node.js"
  # [!code word:scalar]
  # [!code word:vector]
  CollectionSchema{
    name: 'my_collection',
    max_doc_count_per_segment: 10000000,
    fields: [
      FieldSchema[vector]{
        name: 'image_embedding',
        data_type: VECTOR_FP32,
        dimension: 256,
        index_params: HnswIndexParams{metric:COSINE,quantize:UNDEFINED,m:50,ef_construction:500}
      },
      FieldSchema[scalar]{
        name: 'price',
        data_type: INT32,
        nullable: false,
        index_params: InvertIndexParams{enable_range_optimization:true, enable_extended_wildcard:false}
      },
      FieldSchema[scalar]{
        name: 'category',
        data_type: ARRAY_STRING,
        nullable: true,
        index_params: InvertIndexParams{enable_range_optimization:false, enable_extended_wildcard:false}
      },
      FieldSchema[scalar]{
        name: 'image_url',
        data_type: STRING,
        nullable: true,
        index_params: null
      }
    ]
  }
  ```

  ```text tab="Java"
  my_collection [price, category, image_url, image_embedding]
  ```

  1. `"name": "my_collection"`：collection 的名称。
  1. **标量字段**：
      - `"price"`：32 位整数(**必需**)，启用了倒排索引和范围查询优化。
      - `"category"`：字符串数组(**可选**)，启用了倒排索引；但未启用范围查询优化 (该优化对数组类型无意义)。
      - `"image_url"`：字符串(**可选**)，未建索引。

      <Callout className="text-base" type="info">
        如果标量字段的 `index_param` **不为空**，则表示该字段已建立[倒排索引](../../concepts/inverted-index/)。
      </Callout>

  1. **向量字段**：
      - `"image_embedding"`：**256 维**的浮点向量，使用 [HNSW](../../concepts/vector-index/hnsw-index/) 索引，余弦相似度，无量化。

  </Accordion>
</Accordions>

## Collection 统计信息

`stats` 属性提供实时运行状态：

```python tab="Python" tab-group="code-demo"
print(collection.stats)
```

```ts tab="Node.js"
console.log(collection.stats);
```

```java tab="Java"
CollectionStats stats = collection.getStats();
System.out.println(stats);
```

<Accordions type="single">
  <Accordion title="示例">

  ```json tab="Python" tab-group="code-demo"
  {"doc_count":100, "index_completeness":{"image_embedding":1.000000}}
  ```

  ```json tab="Node.js"
  { docCount: 100, indexCompleteness: { image_embedding: 1 } }
  ```

  ```text tab="Java"
  CollectionStats{docCount=100, indexCount=1, indexNames=[image_embedding]}
  ```

  1. `doc_count`：当前存储的 document 总数。
  1. `index_completeness`：向量数据已建立索引的比例 (0.0~1.0)。1.0 表示索引已完成。

  </Accordion>
</Accordions>

## Collection 选项

加载 collection 时传入的选项决定了其运行时行为：

```python tab="Python" tab-group="code-demo"
print(collection.option)
```

```ts tab="Node.js"
console.log(collection.options);
```

```java tab="Java"
try (CollectionOptions options = collection.getOptions()) {
    System.out.printf("readOnly=%b, enableMmap=%b, maxBufferSize=%d%n",
            options.getReadOnly(), options.getEnableMmap(), options.getMaxBufferSize());
}
```

<Accordions type="single">
  <Accordion title="示例">

  ```json tab="Python" tab-group="code-demo"
  {"enable_mmap":1, "read_only":0}
  ```

  ```json tab="Node.js"
  { readOnly: false, enableMMAP: true }
  ```

  ```text tab="Java"
  readOnly=false, enableMmap=true, maxBufferSize=67108864
  ```

  1. `enable_mmap: 1/true` → 已启用内存映射 I/O，可加速访问。
  1. `read_only: 0/false` → Collection 可读可写。

  </Accordion>
</Accordions>

## Collection 路径

`path` 属性返回 collection 在磁盘上的位置：

```python tab="Python" tab-group="code-demo"
print(collection.path)
```

```ts tab="Node.js"
console.log(collection.path);
```

```java tab="Java"
import org.zvec.binding.*;

// Java binding 没有路径 getter —— 请保留传入 open() 的值
String path = "/your/specified/path/";   // [!code highlight]
Collection collection = Zvec.open(path, null);

System.out.println(path);
```

<Callout className="text-base" type="info">
  Java binding 未暴露 collection 路径：底层 C API 只把 `path` 作为 `Zvec.open()` / `Zvec.createAndOpen()` 的入参，并未提供 getter。如果后续需要用到，请自行保存传入的 `path`。
</Callout>

<Accordions type="single">
  <Accordion title="示例">

  ```text
  ./my_collection/
  ```

  此路径与传入 `open()` 的路径一致。

  </Accordion>
</Accordions>
