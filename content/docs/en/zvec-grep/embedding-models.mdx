The Embedding model affects language coverage, memory use, index size, input length, indexing speed, and semantic quality.

## Recommended Starting Points

| Primary content | Start with | Why |
| --- | --- | --- |
| Code | `local/potion-code-16m-v2` | Fast, compact first index |
| English documents | `local/potion-retrieval-32m` | Retrieval-tuned English model |
| Multilingual documents | `local/potion-multilingual-128m` | Covers 101 languages |

Start with the smallest model that covers the required languages and content. Compare representative searches before moving to a larger model.

For a new index, Zvec-Grep resolves `--embedding`, then `ZVEC_GREP_EMBEDDING`, then the configured global default. If none is set, it uses `local/potion-code-16m-v2`. Existing indexes reuse their stored model.

  <Accordion title="Configure and Use Models">

Create an index with the built-in default:

```bash
zg index
```

Override it when another model fits the workspace better:

```bash
zg index --embedding local/potion-multilingual-128m
```

An existing index keeps its stored model. Changing it requires a rebuild:

```bash
zg index --rebuild --embedding local/potion-multilingual-128m
```

Local model files download on first use and are cached under `~/.zvec-grep/models` by default. Workspace content and query text remain on the machine.

Remote models avoid local inference but send disclosed query or workspace content to the configured provider. Zvec-Grep requires separate authorization before doing so.

<Callout type="info" className="text-base">
  Agent MCP approval does not authorize remote Embedding. Remote access is a separate workspace permission.
</Callout>
