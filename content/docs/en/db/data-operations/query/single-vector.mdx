Single-vector search finds documents most similar to a single query embedding. This is the most common search pattern in vector databases.

---

## Prerequisites

This guide assumes you have opened a collection and have a `collection` object ready.

<Accordions type="single">
  <Accordion title="Example Collection Setup">

  This example collection contains two vector fields:

  1. **`dense_embedding`** — A 768-dimensional dense vector using cosine metric
  1. **`sparse_embedding`** — A sparse vector using inner product metric

  It also includes two scalar fields (`publish_year` and `category`).

  ```python tab="Python" title="Open a collection" tab-group="code-demo"
  import zvec

  # [!code word:dense_embedding]
  # [!code word:sparse_embedding]
  collection_schema = zvec.CollectionSchema(  # [!code highlight]
      name="example_collection",
      vectors=[
          zvec.VectorSchema(
              name="dense_embedding",
              data_type=zvec.DataType.VECTOR_FP32,
              dimension=768,
              index_param=zvec.HnswIndexParam(metric_type=zvec.MetricType.COSINE),
          ),
          zvec.VectorSchema(
              name="sparse_embedding",
              data_type=zvec.DataType.SPARSE_VECTOR_FP32,
              index_param=zvec.HnswIndexParam(metric_type=zvec.MetricType.IP),
          ),
      ],
      fields=[
          zvec.FieldSchema(name="publish_year", data_type=zvec.DataType.INT64),
          zvec.FieldSchema(name="category", data_type=zvec.DataType.ARRAY_STRING),
      ],
  )

  collection = zvec.open(path="/path/to/collection")  # [!code highlight]
  ```

  ```ts tab="Node.js" title="Open a collection"
          }
      ],

          {

              name: "category",
  ```

## Performing Single-Vector Search

To perform a single-vector similarity search, use the `query()` method and provide a single [query specification](../#query).

<Accordions type="multiple">

<Accordion title="Dense Vector Search Example">

```python tab="Python" title="Query with a single vector" tab-group="code-demo"
import zvec

result = collection.query(  # [!code highlight]
    queries=zvec.Query(
        field_name="dense_embedding",
        # Dense embeddings are lists of floats
        vector=[0.1] * 768,  # Replace with a real embedding in practice
    ),
    topk=3,
    include_vector=False,  # Do not return the vector embedding
)
print(result)
```

```ts tab="Node.js" title="Query with a single vector"
// Sync
let result = collection.querySync({   // [!code highlight]
    fieldName: "dense_embedding",
    // Dense embeddings are arrays of floats
    vector: Array(768).fill(0.1), // Replace with a real embedding in practice
    topk: 3,
    includeVector: false  // Do not return the vector embedding
});
console.log(result);

// Async
let resultAsync = await collection.query({   // [!code highlight]
    fieldName: "dense_embedding",
    // Dense embeddings are arrays of floats
    vector: Array(768).fill(0.1), // Replace with a real embedding in practice
    topk: 3,
    includeVector: false  // Do not return the vector embedding
});
console.log(resultAsync);
```

```java tab="Java" title="Query with a single vector"
import java.util.Arrays;
import java.util.List;
import org.zvec.binding.*;

// Dense embeddings are arrays of floats
// Replace with a real embedding in practice
float[] vector = new float[768];
Arrays.fill(vector, 0.1f);

try (VectorQuery query = new VectorQuery()) {   // [!code highlight]
    query.setFieldName("dense_embedding");
    query.setQueryVector(vector);
    query.setTopK(3);
    // Do not return the vector embedding
    query.setIncludeVector(false);

    List<Doc> result = collection.query(query);
    for (Doc doc : result) {
        System.out.println(doc.toDetailString());
    }
    Doc.freeDocs(result);
}
```

</Accordion>

<Callout className="text-base" type="warn">
  **Not available in Java yet**: `VectorQuery.setQueryVector()` takes a dense `float[]` only, and `MultiQuery` rejects fewer than two sub-queries, so a single sparse-vector query cannot be expressed in Java. Passing a dense array to a sparse field does not raise an error — it silently returns `-0.0` for every score — so do not work around the limitation that way. To search a sparse field from Java, combine it with at least one other sub-query in a `MultiQuery` and set the vector with `SubQuery.setSparseVector(int[], float[])`; see [multi-vector search](../multi-vector/).
</Callout>

<Accordion title="Query by ID Example">

```python tab="Python" title="Query with a single vector"
import zvec

result = collection.query(  # [!code highlight]
    queries=zvec.Query(
        field_name="dense_embedding",
        id="book_1",  # Uses the 'dense_embedding' of the document with this ID
    ),
    topk=100,
    include_vector=True,  # Returns the vector embedding
    output_fields=["publish_year"],  # Returns the 'publish_year' field
)
print(result)
```

```java tab="Java" title="Query with a single vector"
import java.util.Collections;
import java.util.List;
import org.zvec.binding.*;

// `VectorQuery` has no query-by-id option, so fetch the seed document first
// and reuse its embedding. `fetch()` always returns vector fields.
List<Doc> seedDocs = collection.fetch(Collections.singletonList("book_1"));   // [!code highlight]
float[] queryVector = seedDocs.get(0).getVectorFP32Field("dense_embedding");
Doc.freeDocs(seedDocs);

try (VectorQuery query = new VectorQuery()) {   // [!code highlight]
    query.setFieldName("dense_embedding");
    query.setQueryVector(queryVector);
    query.setTopK(100);
    query.setIncludeVector(true);   // Returns the vector embedding
    query.setOutputFields(new String[]{"publish_year"});   // Returns the 'publish_year' field

    List<Doc> result = collection.query(query);
    for (Doc doc : result) {
        System.out.println(doc.toDetailString());
    }
    Doc.freeDocs(result);
}
```

<Callout className="text-base" type="info">
  **Java**: `VectorQuery` has no query-by-`id` option, so the example above fetches the seed document with `collection.fetch()` and passes its embedding to `setQueryVector()`. `fetch()` always returns vector fields, so no extra option is needed.
</Callout>

</Accordion>

<Callout className="text-base" type="info">

  All queries return a `list[Doc]` containing the **top-k** most similar documents, sorted by relevance score.

  Each `Doc` object includes:

  1. `id`: The document identifier.
  1. `score`: The similarity score.
  1. `vectors`: A map from vector field names to their corresponding embedding values.  
      This is **only populated** if `include_vector=True` is passed in the query.
  1. `fields`: A map from scalar field names to their stored values.  
      By default, **all scalar fields** are returned; this can be restricted using the `output_fields` parameter.

  In Java, queries return a `List<Doc>`. Read the same values with `getPK()`, `getScore()`, `getVectorFP32Field(name)` and the typed scalar getters such as `getStringField(name)` — or print a whole document with `toDetailString()` — then release the results with `Doc.freeDocs()`.

</Callout>

## Parameters

When performing a vector search, the `query()` method accepts two kinds of parameters:

1. **common parameters**, which apply universally regardless of the underlying index type
1. **index-specific parameters**, which allow fine-tuning of search behavior based on the vector index in use

### Common Parameters

Parameter names below use the Python spelling; Node.js uses camelCase (`includeVector`, `outputFields`) and Java uses the corresponding `VectorQuery` setters (`setTopK()`, `setIncludeVector()`, `setOutputFields()`, `setFilter()`).

| Parameter | Description |
| --------- | ----------- |
| `topk` | The number of most similar documents to return. |
| `include_vector` | If `True`, the returned `Doc` objects include the full vector embeddings (disabled by default for performance). |
| `output_fields` | An optional list of scalar field names to include in results. If omitted, all scalar fields are returned. |
| `filter` | An optional SQL-like boolean expression to restrict results. See [filtered search](../filter/) for details. |

<Callout className="text-base" type="warn">
  The `reranker` parameter is part of the `query()` interface but **only applies to [multi-vector search](../multi-vector/)**.  
  Do not provide it in single-vector queries.
</Callout>

### Index-Specific Parameters

You can fine-tune search behavior by passing index-specific query parameters along with the query: the `param` option of the Python `Query` object, `params` in Node.js, or the matching `VectorQuery` setter in Java (`setHNSWParams()`, `setIVFParams()`, `setIvfRabitqParams()`, `setDiskAnnParams()`, …).

The exact type and structure of these `param` depend on the vector index used for the target vector embedding. If omitted, default values are used.

<Callout className="text-base" type="info">

<Accordion title="HNSW Index Example" id="hnsw-example">

If `dense_embedding` uses an [HNSW](../../../concepts/vector-index/hnsw-index/) index, you can adjust the `ef` parameter like this:

```python tab="Python" title="Query with index-specific parameters" tab-group="code-demo"
import zvec

result = collection.query(    # [!code highlight]
    queries=zvec.Query(
        field_name="dense_embedding",
        vector=[0.1] * 768,
        param=zvec.HnswQueryParam(ef=600),  # Set ef to a larger value for better recall [!code highlight]
    ),
    topk=10,
)
print(result)
```

```ts tab="Node.js" title="Query with index-specific parameters"
let result = collection.querySync({   // [!code highlight]
    fieldName: "dense_embedding",
    vector: Array(768).fill(0.1),
    params: { indexType: ZVecIndexType.HNSW, ef: 600 }, // Set ef to a larger value for better recall [!code highlight]
    topk: 10
});
console.log(result);
```

